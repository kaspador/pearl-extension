# Build instructions (AMO source-code review)

This add-on is built from hand-written TypeScript/React/CSS source using Vite.
No source file is hand-minified, transpiled, concatenated, or machine-generated —
only the final bundle (`dist/` for Chrome, `dist-firefox/` for Firefox) is
generated by the build, and that bundle is what is uploaded as the add-on. The
steps below reproduce that bundle exactly.

## Build environment requirements
- **Operating system:** any. Developed and built on Windows 11; the build is
  pure Node.js and also runs on macOS and Linux (no OS-specific tools).
- **Node.js:** v20.19+ or v22.12+ (developed with **v22.18.0**). npm ships with Node.
  - Install from https://nodejs.org/ (LTS), or via nvm: `nvm install 22 && nvm use 22`.
- No other global tools or system packages are required.

## Steps to reproduce
1. Extract this source archive.
2. Install the exact dependencies (pinned by the committed `package-lock.json`):
   ```
   npm ci
   ```
3. Build the Firefox package:
   ```
   npm run build:firefox
   ```
4. The output is in **`dist-firefox/`**. This is exactly the content of the
   submitted add-on archive (`pearl-wallet-firefox.zip` is `dist-firefox/`
   compressed; the manifest at its root is `dist-firefox/manifest.json`).

(For reference, the Chrome build — not submitted to AMO — is `npm run build` → `dist/`.)

## The build script
`npm run build:firefox` (defined in `package.json`) runs, in order:
1. `tsc --noEmit && vite build` — type-check, then bundle with Vite into `dist/`.
2. `node scripts/build-firefox.mjs` — copies `dist/` → `dist-firefox/` and
   rewrites `manifest.json` for Firefox MV3 (event-page `background.scripts`,
   `browser_specific_settings.gecko` id + `data_collection_permissions`).
   It performs **no** transformation of application code.

## Source notes
- All third-party dependencies are open-source and installed from npm
  (`package.json` / `package-lock.json`); none are vendored into `src/`.
- `src/` contains only original, human-readable TypeScript, React (TSX), and CSS.
- The extension is non-custodial: keys/seed/password are generated and stored
  encrypted on-device and never transmitted.
